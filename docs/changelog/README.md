## Changelog Format

Each changelog entry documents:

- **Summary** — What was accomplished
- **Files Created/Modified** — Detailed file listing
- **Database Changes** — Schema updates
- **API Changes** — New or modified endpoints
- **UI Components** — Frontend additions
- **Dependencies** — Package changes
- **What's Next** — Upcoming work
- **Technical Decisions** — Key architectural choices

---

## Version Numbering

We follow [Semantic Versioning](https://semver.org/):

- **MAJOR** (1.0.0) — Breaking changes, production release
- **MINOR** (0.1.0) — New features, backward compatible
- **PATCH** (0.0.1) — Bug fixes, minor improvements
